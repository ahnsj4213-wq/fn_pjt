# ADR-0011: API 규약 — 오류 형식, 상한값, 지원자/담당자 응답 분리, PDF 보기

- 상태: 채택(임시) — 텍스트 모드 제한시간(D 이견 7), 가입 이메일 중복 문구(OQ-34), 탈퇴 중 응시 처리(OQ-12)는 팀 확인이 필요하다
- 날짜: 2026-10-27
- 작성: 에이전트 B / 통합 F
- 관련: PRD SEC-03·04, RPT-03, RES-02·08, INT-13·18, COD-03, AC-03·04·19·21 / OQ-10·12·34 / consolidation C3, C4, C7, T8, T9, T12, T21, T22, T25, T26
- 구현: `app/core/errors.py`, `app/core/middleware.py`, `app/auth/*`, `app/postings/*`, `app/consent/router.py`, `app/resumes/*`, `app/applications/router.py`. 엔드포인트 전체는 TRD 04.

## 맥락

- 지원자·담당자 화면(D), 보안 검사(E), 실시간 면접(C)이 모두 같은 HTTP 계약을 쓴다. 1라운드 리뷰에서 같은 상황의 오류 코드가 설계마다 2~3개였고(B R-13, D-10), 프런트는 코드로 고정 문구(INT-13 등)를 고르므로 이름이 어긋나면 일반 오류 문구가 나간다.
- 지원자 응답에 내부 채점 정보가 섞이면 SEC-04 위반이다(AC-19, R-16). 다른 회사 리소스가 존재 여부라도 드러나면 SEC-03 위반이다(AC-03, R-15).
- 상한값(파일·텍스트·코드)과 PDF 원본 보기 방식은 통합 결정 T22·T26으로 정해졌다.

## 결정

1. **오류 형식**
   - 본문은 `{"error": {"code", "message", "request_id", …추가 필드}}`이고, 코드마다 정해진 추가 필드만 둔다.
   - 입력 오류는 422 `VALIDATION` + `fields: [{loc, type}]`이며, **제출 값은 되돌려 보내지 않는다**(개인정보).
   - DB 변환: `AP001` → 409 `INVALID_STATE`, `AP003` → 409 `SETTINGS_LOCKED`, `AP002` → 500 `INTERNAL`.
   - 코드 이름은 구현된 체계를 기준으로 한 레지스트리 하나(TRD 04 2절)로 관리하고, 레지스트리 밖의 코드는 쓰지 않는다. enum화는 TRD 04 CP-1.
2. **범위 밖 = 없음**: 다른 회사·다른 지원자의 리소스, 잘못된 UUID는 모두 같은 404 `NOT_FOUND`다(`not_found()`). 범위는 세션에서만 오고(`get_for_company`, `get_for_owner`), 요청 본문은 `extra="forbid"`다.
3. **역할 경계**
   - `/api/candidate/*`는 지원자 전용이다(담당자는 403 `ROLE_FORBIDDEN`, USR-05).
   - `/api/recruiter/*`는 담당자 전용이다.
   - 공개 공고·직무 목록은 모든 로그인 사용자가 볼 수 있다(T21). 담당자도 공고 상세를 보고 [지원하기]에서 403을 받으므로 AC-02를 문자 그대로 시험할 수 있다.
4. **인증·CSRF**: 서버 세션 쿠키(HttpOnly, SameSite=Strict, 운영 Secure) + 세션별 CSRF 토큰(`X-CSRF-Token`) + Origin 허용 목록. 가입·로그인에도 Origin을 검사한다. 세부는 ADR-0012(E).
5. **지원자 응답 분리**
   - 지원자 세션이 받는 모든 응답(공개 공고·동의·`/auth/me`·시그널링·오류 포함)은 지원자 전용 모델로만 만들고 담당자 테이블을 읽지 않는다.
   - 공개 공고에는 가중치·커스텀 질문·코딩 문제를 넣지 않는다.
   - 결과의 `feedback`은 결정 뒤에만 채운다(그 전은 `null`). 내용은 항목별 점수·강점·개선점·코딩 통과 여부·RPT-04 문구로 한정한다.
   - 금지 키 목록을 재귀 검사하는 테스트를 품질 게이트(QG-02)에 둔다.
6. **멱등**
   - `Idempotency-Key` 헤더는 쓰지 않고 자연 멱등으로 처리한다.
     - 지원은 `UNIQUE(posting, candidate)`.
     - 제출은 `UNIQUE(application)`.
     - 결정은 `expected_version`.
     - 면접 명령은 `turn_id` + 턴 상태(C3): 현재 턴이 아니면 409 `STALE_TURN`, 같은 턴이 이미 확정됐으면 200.
     - 코딩 임시저장은 클라이언트 단조 `revision`(마지막 쓰기 승리).
   - 재시도한 클라이언트가 409를 받아도 현재 상태로 맞출 수 있게, 409 본문에 `current`·리소스 ID를 넣는다.
7. **명령과 이벤트**
   - 클라이언트→서버 명령(답변 완료, 텍스트 답변, 재개, 텍스트 모드, 하트비트)은 HTTPS로 보낸다(CSRF 적용, T8).
   - 서버→브라우저 이벤트는 데이터채널로 보낸다(TRD 06).
   - WebRTC 시그널링도 `/api` 아래 POST다(CSRF·Origin). 점검 연결은 PREPARING만, 면접 연결은 INTERVIEWING + 슬롯이 조건이다(C4).
   - 텍스트 모드 진입은 서버가 판정한다(T12).
8. **시각·점수**
   - 시각은 UTC ISO 8601이고, 시간에 민감한 응답은 `server_now`를 준다. 공고 마감은 KST 날짜 입력 → 23:59:59 KST 저장이다.
   - 점수는 소수 둘째 자리 문자열이고, 표시값(첫째 자리)은 서버가 만든다(TRD 04 CP-6). 클라이언트는 점수를 계산하지 않는다.
9. **상한값**(T22): 이력서 10 MiB(10,485,760바이트)·50쪽·파싱 20초(하위 프로세스), 텍스트 답변 2,000자, 코드 64 KiB, [실행] 출력 64 KiB·동시 1·10분 20회, 메모 2,000자, 커스텀 질문 5~500자.
10. **PDF 원본 보기**(T26): 권한 API로만 제공한다. `Content-Type: application/pdf`, `Content-Disposition: inline`, `Content-Security-Policy: sandbox`, `nosniff`, `no-store`를 쓰고, 새 탭으로 연다. 원본 파일명은 응답에 쓰지 않는다.
11. **운영 표면**: OpenAPI 문서는 dev·test에서만 연다(T25). 모든 응답에 보안 헤더 기본값과 `X-Request-ID`를 붙인다. 앱 로그에는 경로·상태·지연·ID만 남기고 쿼리·본문은 남기지 않는다.

## 검토한 대안 (장단점)

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| 평면 오류 형식 `{code, message, fields}`(D 1단계안) | 짧다 | 이미 구현된 중첩 형식과 다르다. 이점이 작다 | 기각(구현 유지) |
| 422에 `msg`(입력값 포함 메시지) 노출 | 디버깅 쉬움 | 검증 메시지에 제출 값이 섞여 개인정보가 나갈 수 있다 | 기각(`type`만) |
| 다른 회사 리소스 403 | 원인이 분명하다 | 리소스 존재가 드러난다(SEC-03, E M-행렬) | 기각 |
| 담당자의 공개 공고 조회 403(E 1단계 M-01) | API 묶음이 단순하다 | AC-02 "[지원하기]를 누르면 막힌다"를 시험할 수 없다 | 기각(T21) |
| `Idempotency-Key` 저장 테이블 | 응답 유실 후 같은 응답 재생 | 테이블·만료 관리가 늘고, 대부분 경로가 이미 자연 멱등이다 | 보류(P1). 필요해지면 지원·제출·결정 3개 경로에만 |
| 데이터채널로 명령 전송(A·C 1단계) | 지연이 작다 | 응답 코드·CSRF·감사가 없다. 반쯤 끊긴 채널에서 실패를 알 수 없다(D-05) | 기각(T8) |
| 결정 전 `feedback` 키 생략(D 제안) | 금지 검사가 단순하다 | 구현은 `null`이다. 두 방식 모두 내용이 없다는 점은 같다 | 구현(`null`) 유지 |
| PDF `attachment` 다운로드만(E 1단계) | 브라우저 렌더링 위험이 없다 | 담당자 PC에 파일이 남는다(개인정보 잔존) | 기각(T26 inline + sandbox) |

## 근거

- 1라운드 리뷰: B R-02·R-12·R-13, D-02·D-05·D-08·D-10·D-13·D-15, E M-행렬과 QG-02.
- 실측: aiortc 기본 설정이 외부 STUN을 써서 `iceServers=[]`가 필수다. 컨테이너 기동이 0.45초라 [실행]을 동기 호출(벽시계 10초 + 기동)로 할 수 있다.
- 구현 확인(2026-10-27): 인증·공고·동의·이력서·지원 라우터의 경로·필드·오류 코드를 TRD 04에 그대로 옮겼다.

## 결과와 영향

- TRD 04가 엔드포인트 전체 목록이다. "(구현)" 행은 코드가 원천이다.
- 프런트 타입은 OpenAPI 태그별(`common`·`candidate`·`recruiter`)로 생성하고, 지원자 모듈은 담당자 타입을 import할 수 없다(D 3.2).
- 테스트:
  - 라우트 인벤토리 × 행위자 6종 IDOR 매트릭스(AC-03, 404 본문 동일성 포함).
  - 지원자 세션 전 응답 금지 키·카나리아 검사(AC-19).
  - 오류 코드 레지스트리와 프런트 고정 문구 대조.
  - 가중치 합 99·101·100 경계와 잠금 뒤 변경 시도(AC-21).
  - 같은 공고 동시 지원 10건(AC-04).

## 남은 위험과 재검토 조건

- TRD 04 7절의 변경 제안 CP-1~CP-10이 남아 있다. 특히 지원과 공고 삭제의 경합(CP-2)과 지원 시점 PDF 사본(CP-3)은 데이터 무결성 문제라 우선 처리를 권한다.
- 텍스트 모드 제한시간을 팀이 바꾸면 `text-answer`의 마감 규칙만 바뀐다(API 형식은 같다).
- 페이지네이션이 없는 구현 목록은 규모가 커지면 응답 형식을 `{items, total, page, size}`로 바꿔야 한다(CP-8). 바꿀 때 D 타입을 함께 바꾼다.
