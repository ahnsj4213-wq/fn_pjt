# ADR-0005: 질문 구성과 질문은행 회사 범위
- 상태: 채택(임시) — 커스텀 질문 위치 OQ-36, 이력서 질문 대체 유형 OQ-37은 팀 확인
- 날짜: 2026-10-27
- 작성: 에이전트 C / 통합 F
- 관련: QST-01·02·03·04·06·07, 6.1, P-2, SEC-03, AC-07, X-09, OQ-05·36·37, consolidation-round1 C2·T17·T20, E TH-33·SC-16

## 맥락

- 6.1: 본질문 10개 = 인성 2 · 이력서 2 · 기업 2 · 직무 4, 순서 고정. 커스텀 질문 1개는 직무 질문 하나를 대신한다(X-09).
- QST-01: 은행의 덜 쓴 질문부터, 모자라면 AI가 만들어 은행에 넣되 비슷한 질문은 중복 저장하지 않는다. QST-07: 생성 실패 시 1회 재시도 후 은행. QST-03: 이력서 질문은 이력서에 실제로 적힌 경험·프로젝트만 근거.
- 1라운드 리뷰 C2(B R-01, Critical): AI가 공고·회사 소개로 만든 질문이 회사 구분 없이 공용 은행에 들어가면 X사 정보가 Y사 면접에 출제된다(SEC-03 "어떤 경로로도").
- B 1단계안의 `compose_questions` 작업 시도 3회는 QST-07 "1회 재시도"와 섞일 수 있었다(T17).

## 결정

1. **은행 범위**: `question_bank.company_id`가 NULL이면 팀이 넣은 공용 시드(`source=SEED`)뿐이다. `source=AI`는 `company_id` 필수(DB CHECK). 선택·유사 판정 범위는 `is_active AND (company_id IS NULL OR company_id = 공고 회사)`.
2. **은행에 넣지 않는 것**: 이력서 질문, 꼬리질문, 커스텀 질문(지원자·공고 맞춤 정보).
3. **구성 시점**: READY→PREPARING 때 등록된 `compose_questions` 작업(INTERACTIVE 레인). 면접 시작 조건은 질문 세트 READY(텍스트)뿐, TTS 사전 합성은 조건이 아니다(T20). 결과는 불변 스냅샷(QST-06), 사용 횟수 증가는 면접 시작 트랜잭션.
4. **슬롯 채우기**:
   - 인성(1·2번): 은행, `usage_count` 오름차순·동률 무작위, 이미 고른 질문과 유사하면 건너뜀.
   - 이력서(3·4번): LLM T3로 후보 3개 → 근거 원문 대조 + 질문 본문의 근거 내용어 포함 검사 통과분 2개. 모자라면 1회 재시도, 그래도 모자란 수만큼 **같은 직무군 직무 은행 질문**으로 대체(`source=BANK_FALLBACK`, 슬롯은 RESUME 유지, OQ-37).
   - 기업(5·6번)·직무(7~10번): 은행 우선(직무군 일치), 부족분만 LLM T2 생성. 생성 질문은 `basis_quote`가 공고·회사 소개 원문에 있어야 하고(P-2), 통과분만 `source=AI, company_id=공고 회사`로 은행에 넣는다.
   - 커스텀 질문: **7번(첫 직무 자리)**, 직무는 은행에서 3개(OQ-36 임시. 면접이 중간에 만료돼도 담당자 질문이 출제될 가능성이 높다).
5. **생성 재시도(T17)**: 생성 시도는 슬롯 묶음마다 최대 2회(최초 + 1회 재시도, 코드 상수). 작업 큐의 시도 횟수는 인프라 오류·프로세스 사망 복구용이며 생성 재시도에 쓰지 않는다.
6. **최후 대체**: 생성 2회 실패 + 범위 안 은행 부족 → 회사 무관 공용 시드. 운영 체크리스트에 시드 최소량(인성 10, 범용 기업 4, 직무군별 직무 8)을 둔다.
7. **중복 판정**: 1차 `text_norm_hash`(ADR-0008 양쪽 정규화 + SHA-256) 정확 중복, 2차 `qwen3-embedding:0.6b` 코사인 ≥ 0.85(S-14에서 보정). 둘 다 1번의 범위 안에서만. 은행 삽입 경합은 B의 advisory lock으로 직렬화.

## 검토한 대안 (장단점)

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| 공용 은행 하나(회사 구분 없음) | 은행이 빨리 참 | 회사 간 정보 노출(C2 Critical) | 기각 |
| AI 질문을 은행에 넣지 않음 | 노출 위험 없음 | QST-01 "은행에 더한다" 위반 | 기각 |
| **회사 범위 은행 + 공용 시드** | QST-01 충족, 노출 없음 | 회사별 은행이 처음엔 비어 생성 호출이 많음 | **채택** |
| 커스텀 질문 10번(마지막 직무) | 직무 질문 흐름 유지 | 만료·중단 시 출제 안 될 수 있음 | 기각(OQ-36에서 재확인) |
| 이력서 질문 대체를 인성 은행에서 | 개인 경험을 묻는 성격이 비슷 | 인성 2개와 중복 위험, 직무 관련성 낮음 | 기각(OQ-37) |
| 지원 직후 미리 구성 | PREPARING 대기 제거 | 점검 전에 떠난 지원자에게 LLM 낭비, 설정 변경 반영 어려움 | 기각(설정 불일치 시 재구성 규칙은 유지) |

## 근거

- B R-01 재현: X사 공고 업무란에 카나리아 → 은행 부족 상태에서 X사·Y사 순서로 구성 → Y사 세트에 카나리아가 나오면 실패.
- QST-07 문구("1회 재시도한 뒤 질문은행 질문으로 대체").
- 이미 반영된 스키마: `question_bank`의 `CHECK (source <> 'AI' OR company_id IS NOT NULL)`, `interview_questions.source ∈ {BANK, AI, CUSTOM, BANK_FALLBACK}`, `seq`↔`slot_type` CHECK, CUSTOM은 JOB 슬롯 1개.

## 결과와 영향

- 구성 모듈 `app/questions/compose.py`가 위 순서를 구현하고 각 문항에 `source`, `grounding`, `prompt_version`을 남긴다. LLM 계약 T2·T3는 TRD 05 §6.
- 시험: C2 카나리아(E TH-33), AC-07(근거 없는 질문 → BANK_FALLBACK), QST-07(생성 2회 실패 → 은행, 3회째 호출 없음), 6.1 순서·커스텀 위치.

## 남은 위험과 재검토 조건

- 팀이 OQ-36·37을 다르게 정하면 4번만 바꾼다(스키마 영향 없음).
- 임베딩 임계값 0.85는 초기값이다(S-14). 너무 낮으면 다양한 질문이 버려지고 높으면 중복이 남는다.
- 회사별 은행이 쌓이기 전에는 기업·직무 슬롯마다 생성 호출이 생겨 PREPARING이 길어질 수 있다. `QUESTIONS_NOT_READY` 빈도를 통합 측정에서 본다.
