# ADR-0008: 인용 검증 정규화와 원문 범위 저장
- 상태: 채택
- 날짜: 2026-10-27
- 작성: 에이전트 C / 통합 F
- 관련: EVL-01·02, P-4, AC-16, RES-03, QST-03, 6.2, 6.4, consolidation-round1 C5·C6, E SC-72, B R-04·R-05, D-16

## 맥락

- EVL-02: 인용이 원문과 같은지 코드로 검사하고, 다르면 1회 재생성, 다시 틀리면 '근거 부족'(1점, 6.4). AC-16: 원문에 없는 인용은 '근거 부족'으로 표시.
- 실측: 모델이 "APM 으로", "API 의"처럼 원문에 없는 공백을 넣어 원문 그대로 비교하면 6/20만 일치했다. E의 1단계 규칙(공백 축약)으로는 넣은 공백이 남는다(C5).
- 반대로 C의 1단계 규칙(문장부호·기호 전부 제거)은 숫자·기술명이 다른 위조 인용("3.5배"→"35배", "C"→"C++")을 통과시키고, 저장·표시되는 것이 LLM 문자열이라 원문에 없는 글자가 담당자에게 보였다(C6).

## 결정

1. **대상 텍스트**: 그 호출에서 LLM이 본 같은 답변 단위의 `eval_text`(비식별·간투사 정리본, TRD 05 §8.1). 질문 문장·이력서·다른 문항에서 찾으면 불일치. RES-03 추출값은 PDF 원문, QST-03 근거는 이력서 스냅샷 원문, 6.2 anchor는 답변 eval_text 또는 제공된 이력서 근거 문장이 대상이다.
2. **정규화(양쪽 같게)**: 유니코드 NFKC(문자 단위로 적용해 원문 위치 대응표 유지) → 공백·제로폭 문자 전부 제거 → 따옴표 통일(`“ ” 「 」`→`"`, `‘ ’`→`'`).
3. **인용에만**: 앞뒤 문장부호(유니코드 범주 P와 `~`)를 무시. **내부 문장부호·숫자·기호는 원문과 같아야 한다.** 대소문자 무시·동의어 사전·유사도 매칭은 하지 않는다.
4. **판정**: 정규화 인용이 정규화 원문의 정확한 부분 문자열이고, 정규화 길이 8자 이상(`quote_min_chars`), 150자 이하.
5. **저장**: 일치 위치를 원문 인덱스로 되돌려 `quote_start`, `quote_end`(eval_text의 유니코드 코드포인트 오프셋)와 `quote = eval_text[start:end]`를 저장한다. **LLM이 쓴 문자열은 버린다.** 여러 번 나오면 첫 위치. 불변식 `quote == eval_text[quote_start:quote_end]`.
6. **실패 처리**: 불일치 항목만 이유를 붙여 1회 재생성 → 다시 불일치면 `evidence_status=INSUFFICIENT, insufficient_reason=QUOTE_MISMATCH`, 1점. LLM이 빈 인용을 내면 `NO_EVIDENCE`. 무응답은 `NO_ANSWER`, 매우 짧은 답변은 `TOO_SHORT`(LLM 호출 없음). 근거 부족과 답변 없음은 따로 센다(T19).
7. 규칙 버전 `adr0008-v1`을 manifest에 기록한다(EVL-08).

## 검토한 대안 (장단점)

| 규칙 | 실제 인용 통과 | 위조 통과 | 판정 |
|---|---|---|---|
| 원문 그대로(exact) | 25/48 | 0/7 | 기각: 정상 인용 절반이 근거 부족 |
| E 1단계: NFKC + 공백 축약 | 공백을 넣은 인용 실패(6/20 표본) | — | 기각(C5) |
| NFKC + 공백 전부 제거(ws) | 47/48 | 0/7 | 후보 |
| **ws + 앞뒤 문장부호 무시 + 따옴표 통일(ws_edge)** | **47/48** | **0/7** | **채택**: ws와 같은 성능에 따옴표·끝 마침표 차이를 흡수 |
| C 1단계: 문장부호·기호 전부 제거(ws_punct) | 48/48 | **7/7** | 기각(C6): 위조 전부 통과 |
| E 리뷰안: 2차 문장부호 제거 + 영숫자 토큰 동일성 | 미측정 | 6쌍 거부(E 재계산) | 보류: 구현 복잡, ws_edge로 충분 |

놓친 1개는 모델이 원문의 내부 쉼표("갈렸는데,")를 빼고 인용한 경우다. 재생성 1회로 회복될 수 있고, 회복 못 하면 근거 부족이 되는 것이 EVL-02 문구("원문과 같은지")에 맞다.

## 근거

- `prototypes/results-quote-normalization.txt`: 원문 비교 6/20, 공백·일부 문장부호 제거 20/20.
- `prototypes/results-quote-rules.txt`(`quote_rule_compare.py`): 실제 인용 48개(답변 3개 × 4회 × 4항목, temperature 0.7), 위조 7개(E 리뷰의 쌍 포함: `35배 개선`, `C++ 언어로 구현`, `C# 언어로 구현`, `23명이었습니다`, `11 멘토링을 했습니다`, `오류율을 10 줄였습니다`, `23명이 함께 했습니다`).

## 결과와 영향

- 순수 함수 `verify_quote(source, quote) -> Span | None`(`app/evaluation/quotes.py`), 정규화 함수는 T1·T3·T4와 질문 정확 중복 해시에도 재사용.
- 스키마(반영됨): `answer_evaluations.evidence_status`, `insufficient_reason`, `quote`, `quote_start`, `quote_end`, CHECK(근거 부족·답변 없음이면 1점, OK면 인용 필수).
- D는 서버 오프셋으로만 강조한다. JS는 UTF-16이므로 코드포인트 오프셋을 변환한다. 담당자 리포트 기본 표시 텍스트는 `eval_text`(원문 `transcript`는 토글).
- 시험: AC-16 표 시험에 위조 13쌍(F 7 + E 6), 질문 문장 인용·다른 문항 인용·8자 미만·내부 쉼표 생략 사례, 불변식 속성 시험.

## 남은 위험과 재검토 조건

- 표본이 작다(실제 인용 48개, 한 모델). S-17에서 실제 인용 100개 이상으로 1차 통과 ≥ 95%, 위조 0을 확인한다. 모델·프롬프트가 바뀌면 다시 돈다.
- 1차 통과율이 낮으면 프롬프트("띄어쓰기·문장부호까지 그대로")를 먼저 고친다. 규칙을 느슨하게 바꾸려면 위조 세트 0 통과를 조건으로 이 ADR을 개정한다.
