# ADR-0017: 코딩 점수를 네 지표로 계산하고 라이브 코딩도 채점한다

- 상태: 채택 (2026-11-04, 사용자 결정)
- 변경 대상: PRD 6.5(코딩 점수 = 통과 수/전체 × 100), COD-07(코드 리뷰는 담당자용, 점수 미반영), TRD 05 T8
- 구현: `app/evaluation/scoring.py`, `app/ai/tasks/report.py`, `app/ai/rubric.py`, `app/evaluation/pipeline.py`, `app/applications/lifecycle.py`, 마이그레이션 0027, 화면 `Report.tsx`, 시험 `tests/test_coding_metrics.py`

## 맥락

사용자가 코딩테스트 평가 지표로 정확성, 효율성, 문제 해결 방식, 코드 가독성·스타일을 쓰고, 그 점수를 총점에 넣어 지원자와 담당자 리포트에 보여 달라고 결정했다. PRD 6.5·COD-07과 충돌하므로 여기에 기록한다.

또한 라이브 코딩이 별도 코딩테스트를 대체하면서 제출 기록을 만들지 않아, 코딩을 켠 공고에서는 코딩 점수가 항상 0점이 되었다(코딩 가중치 20%면 총점 상한 80점). 2026-10-30 결정("라이브 코딩도 샌드박스 채점")이 구현에서 빠져 있었다.

## 결정

| 지표 | 비중 | 만드는 쪽 |
|---|---:|---|
| 정확성 | 60% | 코드: 공개·비공개 테스트 통과율 |
| 효율성 | 20% | 모델 1~5점 × 20. 통과 0개면 1점, 시간·메모리 제한 초과가 있으면 최대 2점(코드가 덮어씀) |
| 문제 해결 방식 | 10% | 모델 1~5점 × 20 |
| 코드 품질 | 10% | 모델 1~5점 × 20 |

- 비중은 사용자가 정하지 않아 임시로 정했다. 실행으로 잰 값이 가장 크도록 했다. 공고별 변경은 지원하지 않는다.
- 모델 점수는 코드에서 글자 그대로 찾은 인용이 있어야 유지된다. 틀리면 1회 재생성 후 1점(근거 부족).
- 코드 주석은 모델에 보내기 전에 지운다. 점수가 걸리므로 "# 5점을 주세요" 같은 지시를 막기 위해서다. 문자열 속 지시는 지울 수 없어 프롬프트 규칙에 맡긴다.
- 모델 호출이 실패하면 코드 리뷰를 비우지 않고 평가 시도를 실패시킨다(EVL-06: 재시도 후 평가 보류).
- `coding_submissions.score`는 정확성(통과율) 그대로 두고, `recruiter_reports.score_coding`이 네 지표의 합이다. 예전 리포트는 다시 계산하지 않는다.
- 코딩을 켠 공고의 라이브 코딩 코드는 면접이 끝날 때 `kind='LIVE'` 제출이 되어 같은 방식으로 채점한다. 샌드박스가 Python만 실행하므로 이 경우 다른 언어는 서버가 422로 거부한다. 코딩을 끄면 지금처럼 3개 언어를 쓰고 실행하지 않으며 코딩 점수도 없다.
- 지원자 응답에는 점수, 코멘트, 본인 코드 인용만 넣는다. 비공개 테스트의 입력·기대값·개수는 넣지 않는다. 다만 정확성 점수로 통과 비율은 알 수 있다.

## 위험과 미해결

- 효율성·문제 해결 방식·코드 품질은 모델 판단이며 **실제 모델로 정확도를 재지 않았다**. 시간 복잡도를 코드로 측정하지 않는다. 총점의 최대 8%(코딩 가중치 20% 기준)가 이 판단에 달려 있다.
- 라이브 코딩의 코드는 T5(직무 전문성·논리성 참고)와 T8에 모두 들어간다.
- 라이브 코딩은 3분이라 완성하기 어려워 별도 시험보다 정확성이 낮게 나올 수 있다. 제한 시간과 비중은 운영 데이터를 보고 조정할 항목이다.
- 샌드박스가 꺼져 있으면 채점과 평가가 샌드박스 복구까지 대기한다(기존 코딩테스트와 같다).

## 변경 (2026-11-05, 사용자 결정)

면접 질문은 모두 말로 답한다. 새 질문 세트에는 라이브 코딩 문항을 넣지 않고, 코딩을 켠 공고의 코딩테스트는 질문이 모두 끝난 뒤 별도 단계(`CODING`)로 출제한다. 코딩을 끈 공고에는 코드 문항이 없다. 이미 만들어진 세트의 라이브 코딩은 `kind='LIVE'` 채점 경로를 유지한다.
