# ADR-0023: 답변 평가 — 질문 유형별 루브릭, 근거는 문장 번호, 근거 상태 구분, 독립 판정 중앙값

- 상태: 채택 (2026-11-09, 사용자 지시)
- 관련 요구사항: EVL-01·02(P0, EVL-02 처리 방식 변경), RULE-6.3, RULE-6.4(근거 부족 1점의 적용 범위 변경), AC-16, OQ-38, X-11
- 바뀐 버전: `evaluate_answer@1.4.0 → 2.0.0`, `rubric-v3 → rubric-v4`, migration 0033(`answer_evaluations` 근거 상태 제약)

## 배경

실제 면접 리포트에서 두 가지가 확인됐다(DB의 `answer_pre_evaluations`로 확인).

1. 내용이 있는 꼬리질문 답변(Q3-1)이 4개 항목 모두 1점(20점). 모델이 두 번 모두 인용을 비워 냈고, 규칙상 인용이 없으면 `INSUFFICIENT/NO_EVIDENCE` 1점이었다.
   화면은 이 1점을 판정 점수처럼 보여 줬다. 답변 수준이 아니라 인용 추출 실패가 점수를 정했다.
2. 우선순위만 말하고 이유·확인 방법이 없는 한 문장 답변(Q6)이 4개 항목 모두 5점(100점). 인용 4개는 원문과 맞았고, 모델 점수를 그대로 썼다.

사용자 지시(2026-11-09): 4개 항목·1~5점·"AI가 점수를 정하고 백엔드는 형식·근거만 검증" 원칙은 유지한다. 논리성은 육하원칙을 참고하되
문제 상황·원인 분석·판단 근거·대안 검토·실행·결과 검증·인과의 일관성을 종합해 보고, 질문 유형(경험·행동·기술·설계·상황 대응)에 따라
필요한 요소를 다르게 적용한다. 논리성(사고·판단 과정)과 전문성(직무 지식·적용의 정확성)을 분리한다. 근거 추출 실패만으로 최저점을
주지 않는다. 근거 추출 실패·실제 내용 부족·답변 없음·평가 불가를 구분한다. 짧다는 이유만으로 낮은 점수를 주지 않는다. 다양한 답변으로 회귀 시험한다.

## 결정

### 1. 루브릭 v4 (`app/ai/rubric.py`)
- 전문성: 직무 지식·기술 자체의 정확성, 적용 방법(도구·절차·수치·조건)의 구체성, 직무와의 맞음. "왜 그 방법을 골랐는지"는 보지 않는다.
- 논리성: 사고·판단 과정과 인과의 일관성. 지식이 맞는지는 보지 않는다. 육하원칙은 참고만 하고 개수를 세지 않는다.
- 5개 수준마다 기준 문장과 예시(같은 장면 "느려진 API"로 4항목 모두). 공통 문장: 항목은 서로 독립, 길이로 판단하지 않음.
- 질문 유형 `QUESTION_KINDS`: 경험(결과와 그 확인 필요), 행동·가치관(결과·대안 필수 아님, 전문성은 직무 맥락으로 보고 기술 용어가 없다고 낮추지 않음 — OQ-38),
  기술 지식(원리·조건, 사례 필수 아님), 설계(선택지 비교·선택 근거·검증), 상황 대응(우선순위와 근거·실행·확인).
  유형은 코드가 영역과 질문 문구로 정해 입력으로 넘긴다(`question_kind`). 점수가 아니다.

### 2. 근거는 문장 번호 (`quotes.sentences`, `evaluate.py`)
코드가 답변을 문장으로 나눠 번호를 붙이고, 모델은 항목마다 번호만 쓴다. 저장하는 인용은 그 문장의 원문 범위다(ADR-0008의 "모델 문자열이 아니라 원문 범위" 유지).
모델이 문장을 옮겨 적지 않으므로 잘못 옮기거나 지어낼 수 없다. 점수 전에 `found`(문제·원인·근거·대안·실행·결과·지식이 드러난 문장 번호)를 먼저 쓰게 해
답변을 읽은 뒤 판정하게 했다(보정에서 효과 확인, 아래). `found`는 점수 계산에 쓰지 않는다.

### 3. 근거 상태

| 상태 | 뜻 | 점수 | 화면 |
|---|---|---|---|
| OK | 근거 문장이 있는 판정 | 모델 | 하이라이트 |
| UNLINKED | 3점 이상인데 문장을 못 가리킴(1회 재요청 후) | 모델 점수 유지 | `*` + "근거 미연결" |
| INSUFFICIENT/LOW_CONTENT | 1~2점이고 가리킬 문장이 없음 | 모델(1~2) | `*` + "내용 부족" |
| INSUFFICIENT/TOO_SHORT | 규칙: 15자 미만·무내용 | 1 | `*` + "내용 부족" |
| NO_ANSWER | 무응답 | 1 | "답변이 없었습니다" |
| (이전 실행) QUOTE_MISMATCH·NO_EVIDENCE | 2.0.0 이전 추출 실패 최저점 | 1 | `*` + "근거 추출 실패, 재평가하면 현재 기준" |

평가 불가(재시도 후에도 모델 출력 없음)는 항목 상태가 아니라 평가 시도 실패다: 리포트는 평가 보류, 재평가(EVL-06), 임시 점수 없음.

### 4. 독립 판정 중앙값 (`pipeline.evaluate_unit`, `AIHIRE_EVAL_SAMPLES` 기본 3)
같은 답변을 3번 독립 판정하고 항목마다 점수가 중앙값인 판정을 근거 문장·코멘트째 쓴다. 남는 점수는 항상 모델이 낸 점수 중 하나이며,
코드는 점수를 만들거나 고치지 않고 모델 판정 중 가운데를 고른다. 짝수(표본 하나 실패)면 낮은 쪽. 규칙 결과는 반복하지 않는다.

## PRD와의 충돌 (기록)
- EVL-02·RULE-6.4 "재실패 시 '근거 부족' 1점": 문장 번호 방식에서 근거 연결 실패는 1점이 아니라 `UNLINKED`(모델 점수)다. 사용자 지시 5번
  ("근거 추출 실패만으로 실제 답변을 최저점 처리하지 마세요")에 따른 변경. 규칙 기반 '근거 부족'(TOO_SHORT)과 '답변 없음' 1점은 그대로.
- AC-16 "모든 점수에 원문 인용": `UNLINKED`·`LOW_CONTENT`는 인용이 없다. 대신 화면이 그 사실을 표시하고, 원문에 없는 인용은 구조적으로 생길 수 없다.

## 보정 결과 (실제 모델, 2026-11-09, `scripts/eval_calibration.py`)

장비: 개발 PC의 `llm-gpu`(llama.cpp server-cuda, `qwen3.5-4b.gguf`, 컨텍스트 8192, 슬롯 2, BATCH는 슬롯 1). 답변 14개(경험 4, 기술 3, 상황 대응 2,
꼬리질문 1, 행동 2, 설계 2), 기대 범위는 실행 전에 작성자가 정했다(사람 평가자 합의가 아님).

| 단계 | 논리성·전문성 기대 범위 일치 | 근거 미연결 | 순서 역전 |
|---|---|---|---|
| v4 루브릭만 (found 없음) | 11/27 | 13/56 항목이 근거 없음 | 0 |
| + found 단계 | 20/27 | 0 | 1 |
| + 1·2점 경계, 유형별 상한 완화 | 22/27 | 0 | 0 |
| + 보정 세트의 직무 요약 수정(IoT 문항) | 24/27 | 0 | 0 |

- 원래 문제 사례(1표본 측정): Q3-1형 답변 → 논리성 2~3·전문성 2~3, Q6형 답변 → 논리성 2·전문성 2~3.
- 같은 내용의 1문장 답변과 4문장 답변: 둘 다 논리성 5·전문성 4~5(짧다고 낮아지지 않음). 길지만 빈 답변: 1점.
- 일관성: temperature 0·seed 고정에서도 같은 답변 3회 판정의 항목 점수가 최대 3점까지 달라졌다(1표본: 불안정 항목 11/56).
  프롬프트 캐시를 끄고 다시 재도 15/56으로 같았다(캐시 문제가 아니라 GPU 연산의 비결정성과 4B 모델의 경계 판단).
  중앙값 3표본(`--samples 3 --repeat 3`, 14답변×4항목=56): 2점 이상 흔들린 항목 11/56. 그중 논리성·전문성은 1개(설계 모범답안 논리성 5/5/3)로,
  1표본 측정의 3~4개에서 줄었다. 나머지 10개는 표현 및 태도·전달력이며 중앙값으로도 줄지 않았다(두 항목이 함께 3↔5로 움직임).
  따라서 중앙값은 논리성·전문성의 일관성에는 효과가 있고, 태도·전달력의 흔들림은 남은 위험(R-26)이다.
- 같은 측정에서 원래 문제 사례: Q3-1형 꼬리질문 답변 논리성 1~2·전문성 1~2(이전: 근거 추출 실패로 4항목 모두 1점),
  Q6형 한 문장 답변 논리성 2~3·전문성 2~3(이전: 4항목 모두 5점).

## 영향과 위험
- 평가 호출이 답변당 3배(답변당 약 8초 → 약 24초, GPU 슬롯 1). 면접 중 사전 평가가 실시간 레인(꼬리질문 판단·질문 생성)과 GPU를 나눠 쓰므로
  지연이 늘 수 있다. 동시 응시 한도(INT-13)와 함께 측정 필요(미측정). 부하가 크면 `AIHIRE_EVAL_SAMPLES=1`로 되돌릴 수 있다.
- 기대 범위는 작성자 판단이다. 사람 평가자 골든셋(Kappa)은 여전히 없다(TRD 05 골든셋 계획, X-11).
- 4B 모델은 좋은 답변의 일부 요소를 놓친다(상황 대응 모범답안 논리성 3, 기대 4~5). 더 큰 모델이나 판정 분리는 후속 과제.
- 이전 리포트의 점수는 바뀌지 않는다(재평가해야 새 기준). 화면은 이전 실행의 추출 실패 1점을 "근거 추출 실패"로 표시한다.
