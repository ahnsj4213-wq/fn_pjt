# ADR-0026: rubric-v5 — 예시 유사도가 아니라 루브릭 요소와 답변의 의미로 판정

- 상태: 채택 (2026-11-09). 운영 반영(api·worker 재빌드)은 사용자 결정 대기다.
- 근거: 사용자 지시 2026-11-09 (평가 공정성 9개 항목)
- 변경:
  - ADR-0023의 rubric-v4를 rubric-v5로 바꾼다.
  - `evaluate_answer@2.0.0`을 `@2.1.0`으로 올린다.
  - 4개 항목, 1~5점, 모델이 점수를 정하는 원칙, 서버 검증·집계 원칙은 그대로다.

## 결정

1. **점수별 예시는 "참고 사례"다.**
   - 예시와 문장·표현·기술·길이가 비슷한지로 점수를 정하지 않는다. 점수별 기준 문장과 답변의 의미를 비교한다.
   - 같은 내용을 다른 말로 한 답변은 같은 점수다.
2. **논리성은 질문 유형별로 본다.**
   - 경험 질문: 상황·판단·행동·결과
   - 기술 질문: 개념·이유·일관성. 경험 사례, 결과 검증, 대안 검토는 필수가 아니다.
   - 설계 질문: 요구사항·대안·트레이드오프
3. **육하원칙은 필요한 맥락이 빠졌는지 확인하는 도구다.** 체크리스트로 쓰지 않는다.
4. **태도와 전달력도 질문 유형별 관점을 둔다.**
   - 지원자 수준(`career_level`, 경력 기간만 사용)으로 기준을 해석한다. 이력서에서 평가 입력에 들어가는 것은 이 수준 값 하나다.
   - 신입은 학교·팀 프로젝트도 경험으로 본다.
   - 수준은 해석에만 쓰고 점수를 일괄로 올리거나 내리지 않는다.
5. **짧아도 정확하고 충분하면 5점을 줄 수 있다.**
6. **근거는 답변 원문에 있는 사실만 쓴다.**
   - 코멘트에 참고 사례에만 나오는 단어(`rubric.EXAMPLE_TERMS`)가 있고 답변에는 없으면, 모델에 한 번 다시 묻는다.
   - 다시 물어도 남으면 코멘트만 지운다. 점수는 모델의 것을 그대로 두고, `example_leak` 플래그를 남긴다.
7. **서버는 점수를 바꾸지 않는다.** 형식·범위·근거 문장 검증, 3회 판정의 중앙값 선택, 집계만 한다.

## 측정 (실제 모델, `tools/eval_consistency.py`, `backend/tests/data/eval_consistency.json`)

조건:
- 합성 답변 18개를 썼다. 질문은 경험·기술·설계 3개이고, 질문마다 우수·보통·부족 3수준이며, 수준마다 표현만 다른 답변 2개다.
- 판정은 운영과 같게 3회 판정의 중앙값이다.
- 모델은 llama.cpp `qwen3.5-4b`(GTX 1660 SUPER)다.
- 면접 E2E가 아니다. 평가 작업만 호출했고 DB에는 쓰지 않았다.

| 지표 | v4 | v5 |
|---|---|---|
| 우수 > 보통 > 부족 순서 (3개 질문) | 2/3 (설계: 보통 4.0 < 부족 5.5) | **3/3** |
| 짧은 우수 답변 / 긴 우수 답변 (기술, 합계 20점 만점) | 18 / 19 | **20 / 20** |
| 예시 장면(인덱스) 답변 / 다른 장면 같은 수준 답변 (경험 우수, 합계) | 10 / 10 | 12 / 12 |
| 같은 수준 쌍 항목별 차이 평균 / 1점 이하 비율 | 0.28 / 36 중 36 | 0.36 / 36 중 34 |
| 3회 판정 간 차이 평균 / 최대 | 0.42 / 2 | 0.50 / 2 |
| 코멘트에 답변에 없는 예시 단어 | 1 | **0** |
| 근거 미연결(UNLINKED) | 0 | 0 |
| 답변 1개 평가 시간(3회) | 23.9 s | 33.1 s |

남은 한계(모델 능력):
- 우수 경험 답변이 여전히 4개 항목 모두 3점이다.
  - 모델 코멘트가 답변과 맞지 않는다. 답변에 "캐시도 생각했지만 원인을 가리는 방법이라 판단해"가 있는데도 "대안 검토가 명확하지 않다"고 썼다.
- 설계 우수 답변 두 개가 표현만 다른데 합계 12점과 7점으로 갈렸다.
  - 7점 쪽 전달력 1점의 코멘트는 "핵심이 앞부분에 있으나"였다. 1점 기준과 맞지 않는 판정이다.
- 4B 모델이 긴 답변의 요소를 놓치는 문제다. 프롬프트로 더 줄이기 어렵다. 다음 후보는 평가 모델 교체, 또는 `found`(요소별 문장 번호)와 점수가 모순되는 판정을 다시 묻는 검사다.

## 서버 측 규칙과의 관계 (사용자 결정 필요)

- `details.py` 측정값이 항목 점수의 30%로 섞인다(`RULE_WEIGHT`).
  - 태도는 답변 시간(제한 시간의 35% 미만이면 감점)과 부정 표현 수로 섞인다.
  - 전달력은 말 속도·뚜렷함·높낮이로 섞인다.
  - 짧지만 정확한 답변도 태도 점수가 낮아질 수 있어 5번 원칙과 부딪힌다.
- `TOO_SHORT`(15자 미만이면 모델 호출 없이 1점)는 기존 규칙(OQ-09)이다.
- 이번에는 둘 다 바꾸지 않았다.
