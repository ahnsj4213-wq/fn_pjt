# ADR-0021 코딩테스트 문제은행 Lv.0~5와 지원 건별 출제

- 상태: 채택 (사용자 요청, 2026-11-05)
- 관련: COD-01~06, AC-15, ADR-0018(화면 표준), `docs/TRD.md` 3장, `docs/TRD.md` 4장
- 변경되는 이전 결정: "서버가 하~중 난이도 틀 11개에서 무작위로 정해 공고에 고정"

## 맥락

문제가 11개뿐이고 난이도가 하·중에 몰려 있어, 경력 수준을 가리기 어렵고 같은 공고 지원자가 전부 같은 문제를 받았다. 사용자는 Lv.0~5의 다양한 유형, 충분한 설명, 직무·경력·난이도에 따른 선정, 최근 출제 회피를 요구했다. "문제 수만 늘리고 실제로 채점되지 않는 문제를 완료 처리하지 말 것"이 조건이다.

## 결정

1. **원본만 쓴다.** 문제 상황·설명·입출력·예제·테스트·풀이는 전부 직접 작성한다. 다른 사이트 문제를 옮기거나 크롤링하지 않는다. 사용자가 준 블로그는 첫 페이지의 글 제목만 읽었고 본문은 읽지 않았다. 아이디어를 얻은 4문제에 그 URL을 `source.reference_urls`로 남기고, `upstream_url`은 원본이므로 `null`이다.
2. **은행 구성.** `app/coding/templates.py`가 기존 11개와 `bank_basic.py`(Lv.0~2), `bank_advanced.py`(Lv.3~5)를 합친 55문제를 낸다. Lv.0 7, Lv.1 11, Lv.2 11, Lv.3 12, Lv.4 7, Lv.5 7. 모든 문제는 Python 3 시작 코드, 설명 붙은 공개 예제, 지원 건별로 생성되는 비공개 테스트, 정답 풀이를 갖는다.
3. **레벨 기준**(`app/coding/levels.py`).

   | Lv | 응시 시간 | 실행 제한 | 난이도 |
   |---|---|---|---|
   | 0 | 15분 | 2초 | 하 |
   | 1 | 20분 | 2초 | 하 |
   | 2 | 30분 | 3초 | 중 |
   | 3 | 40분 | 4초 | 중 |
   | 4 | 50분 | 5초 | 상 |
   | 5 | 60분 | 6초 | 상 |

4. **선정**(`app/coding/selection.py`). 지원자는 고르지 않는다. 레벨은 공고 하나에 하나다: 직무(개발·데이터 외는 Lv.1), 경력(신입 2, 경력 3, 5년 이상 4, 10년 이상 5), 담당자가 정한 난이도(쉽게 -1, 어렵게 +1)로 정하고, 제한 시간에 못 푸는 레벨이면 낮춘다. 같은 레벨 안에서 이 지원자가 이미 받은 문제, 이 공고의 최근 30건에서 나온 문제를 피한다. 담당자가 API로 특정 문제를 지정하면(`coding_selection = FIXED`) 그 문제를 쓴다.
5. **공개 범위.** 지원자에게는 레벨·제한·시작 코드까지만 보낸다. 알고리즘 태그는 힌트이고 출처는 필요 없는 정보라 담당자 화면에만 보인다. 비공개 테스트는 지금처럼 지원 건 사본에만 있다.
6. **채점은 그대로다.** 기존 샌드박스와 채점기를 쓰고, 점수는 통과 수 / 전체 수다. 레벨은 AI 코드 리뷰 프롬프트에 `level_expectation`(기대 수준)으로만 들어가며 점수 계산에 쓰지 않는다. 프롬프트 버전 `code_review@2.1.0`.
7. **화면.** 위에 레벨·제목·Python 3·제한·저장 상태·타이머·진행 막대, 왼쪽에 문제 설명, 오른쪽에 편집기와 실행 결과·테스트케이스 탭, 아래에 초기화·실행·최종 제출. 레이아웃만 흔한 코딩 시험 구성을 따르고 색·글꼴은 서비스 토큰을 쓴다. [실행]은 입력·기대 출력·내 출력을 나란히 보여 주되 판정은 하지 않는다(AC-15).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 지원자마다 레벨을 다르게 | 같은 공고 지원자끼리 점수를 비교할 수 없다 |
| 지원자가 문제를 선택 | 쉬운 문제로 쏠리고 비교가 어렵다 |
| 공고에 문제 하나 고정(이전 결정) | 유출 시 영향이 공고 전체에 미친다. 다만 레벨 내 문제 난도 차이는 이번 결정의 단점으로 남는다 |
| 태그를 지원자에게 공개 | 어떤 알고리즘인지 알려 주는 힌트가 된다 |

## 영향

- 같은 공고 지원자가 다른 문제를 받으므로, 같은 레벨이라도 문제별 난도 차이가 점수에 섞일 수 있다(`docs/risks.md` R-24). 담당자 화면에 문제와 레벨을 표시해 해석을 돕는다.
- 마이그레이션 `20261105_0029`: `coding_problems`에 `level, tags, families, starter_code, source`, `job_postings`에 `coding_selection, coding_difficulty`. 기존 공고의 `coding_problem_id`는 대체 경로로 남고, 기존 공고는 AUTO가 된다.
- 비공개 입력은 지원 건마다 DB에 저장되므로 문제당 약 400 KB 이내로 줄였다. 실행기의 입력 상한 1 MB에 맞춘 것이며, 그만큼 문제의 제한사항(`n` 범위)이 정해졌다.

## 검증

- `backend/tests/test_coding_bank.py`: 문제 구성, 예제 설명, 씨앗별 입력, 입력 크기, 후보 프로그램 실행, 독립 풀이 28종과 일치, 선정 규칙.
- `tools/verify_coding_bank.py`: 모든 문제의 정답 풀이를 **실제 샌드박스와 채점기**로 돌려 전부 통과, 틀린 프로그램은 실패, 시작 코드는 정상 실행을 확인한다.
- `frontend/e2e/candidate-flow.spec.ts`: 브라우저에서 코드 입력 → 실행 → 제출 → 자동 채점 → 평가.
- 실행 결과는 `docs/requirements-traceability.md`의 COD 행에 기록한다.

## 확장 지점

담당자 문제 등록 화면은 만들지 않는다(사용자 결정). 문제 추가는 틀과 마이그레이션으로 한다.
