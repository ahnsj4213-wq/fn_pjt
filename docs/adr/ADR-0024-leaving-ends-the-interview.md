# ADR-0024: 면접 도중 나가면 그대로 종료 — 이어하기·그만두기·다시 보기 없음

- 상태: 채택 (2026-11-09, 사용자 지시)
- 관련 요구사항: INT-11·AC-13(P0, 변경), INT-12, INT-18(P1, 일부 변경), OQ-07, OQ-21, OQ-25, COD-05
- 사용자 지시(2026-11-09): "'면접 이어서 하기', '면접 그만두기' 이런 기능 빼버려. 면접자가 그냥 중간에 나가면 그걸로 끝이야. 면접 다시 보기 그런 기능도 넣지말고."

## 결정

1. 면접(코딩테스트 포함) 도중 창을 닫거나, 새로고침하거나, 다른 페이지로 가거나, 음성 연결이 끊기거나, 신호가 120초 없으면 응시는 그 자리에서 끝난다.
   - 상태: `INTERVIEWING|CODING → INTERRUPTED → EXPIRED`(한 트랜잭션, `lifecycle.end_left`). 전이표가 `INTERVIEWING → EXPIRED`를 허용하지 않아 INTERRUPTED를 거친다. 마이그레이션 없음.
   - 진행 중이던 문항은 버린다(OQ-21 그대로). 답한 본질문은 평가한다(OQ-07: 1개 이상이면 평가 작업 등록, 0개면 평가 없음).
   - 코딩테스트 중이면 마지막 저장 초안을 그때 제출(`AUTO_EXPIRED`), 라이브 코딩은 쓴 코드가 있을 때만 제출.
   - 슬롯 반환, 담당자 알림("중간에 멈췄습니다")은 그대로.
2. 다시 들어올 수 없다.
   - `POST …/interview/resume`, `POST …/interview/retake`(테스트 공고 다시 보기, `AIHIRE_RETAKE_POSTING_IDS`) 삭제. `app/interview/retake.py` 삭제.
   - 음성 연결(`POST …/rtc/offer`, INTERVIEW)은 응시당 한 번: 이미 질문이 나간 응시에 새 연결이 오면 응시를 끝내고 409 `ATTEMPT_ENDED`. 살아 있는 연결이 있으면 다른 창의 연결은 409 `ALREADY_CONNECTED`(진행 중인 면접은 유지). 서버가 강제하므로 화면을 우회해도 이어갈 수 없다.
   - 예전 버전에서 INTERRUPTED로 남은 응시는 `attempt_sweeper`가 같은 방식으로 끝낸다.
3. 화면
   - "면접 그만두기" 버튼, "면접 이어서 하기"·"코딩테스트 이어서 하기" 버튼과 문구, 자동 재연결(1·2·4초 백오프) 삭제.
   - 시작 화면 버튼은 "면접 시작" 하나(브라우저 자동재생 정책 때문에 한 번은 눌러야 한다). "도중에 나가면 종료되며 다시 이어서 하거나 다시 볼 수 없다"고 안내.
   - 면접·텍스트 모드 중 창을 닫거나 새로고침하면 브라우저가 한 번 확인한다(`beforeunload`).
   - 연결이 끊기면 "연결이 끊겨 면접이 종료되었습니다. 답변한 질문까지 평가됩니다" 후 완료 화면.
   - 지원 현황: 중단된 응시는 "중도 종료 (질문 n/m)", 답한 질문이 있으면 [리포트 보기]. [다시 지원] 없음. 진행 중 응시에 [이어서 하기] 없음.
4. 텍스트 모드(INT-18)는 첫 음성 연결이 3번 실패했을 때(아직 질문이 나가기 전)와 같은 질문의 음성 제시 한도에 걸렸을 때만 남는다. 면접 도중 끊긴 연결을 텍스트로 이어 가는 경로는 없다.

## PRD와의 충돌 (기록)

| 항목 | PRD | 변경 |
|---|---|---|
| INT-11 / AC-13 (P0) | 끊김·새로고침 후 재진입하면 끊긴 문항부터, 저장 답변 유지 | 재진입 없음. 저장 답변은 유지되어 평가된다. 끊긴 문항부터 다시 하는 부분만 없어진다 |
| INT-18 (P1) | WebRTC 자동 재연결, 실패 시 텍스트 입력 | 면접 도중 자동 재연결 없음. 시작 시 연결 실패 → 텍스트 모드는 유지 |
| OQ-25 / COD-05 | 끊긴 동안에도 마감 시각에 마지막 초안 자동 제출 | 나간 시점에 바로 마지막 초안 제출(마감을 기다리지 않음) |

## 영향과 위험

- 순간적인 네트워크 끊김(`DISCONNECTED_GRACE_SEC` 이상)이나 오디오 수신 중단(`NO_AUDIO_SEC`)도 면접을 끝낸다. 지원자 탓이 아닌 장애로 응시 기회를 잃을 수 있다(R-29).
- 실수로 새로고침해도 끝난다. 브라우저 확인 창 하나가 유일한 보호 장치다.
- 서버 재시작으로 음성 세션이 사라진 경우도 재연결 시 종료로 처리된다.
- 확장 지점: 장애 원인(서버·네트워크)별로 예외를 두려면 `end_left` 호출 전에 원인을 구분하면 된다(미구현).
