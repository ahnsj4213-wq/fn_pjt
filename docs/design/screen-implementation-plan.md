# 화면정의서 구현 계획

> 기준 문서: `docs/design/screen.md` (화면정의서 v0.1, 와이어프레임 v14, 33개 화면).
> 작성 2026-10-30. 화면정의서의 캡처(`docs/design/screens/*.png`)는 아직 저장소에 없다.

## 0. 결정 사항 (2026-10-30, 사용자 확인)

| 쟁점 | 결정 |
|---|---|
| AI 예상 합격 (75점 이상 합격 추천 / 65~74 보류 / 그 아래 불합격 추천) | 화면정의서대로 넣는다. **LLM이 아니라 코드가 점수 구간으로 계산**하고, 담당자에게만 보이며, '참고값'이라고 안내한다. P-8은 "LLM 출력에 합격·불합격 표현 금지"로 범위를 좁힌다. |
| 시선 추적, 표정·긴장도, 화이트보드 그림 평가 | 시선 이탈만 **브라우저 얼굴 인식**으로 감지해 경고하고 횟수를 기록한다. 표정·긴장도 그래프는 '준비 중'으로 둔다. 화이트보드는 그림을 저장하고, **말로 한 설명만** 평가한다(비전 모델 없음). |
| 라이브 코딩 | 면접 질문 하나(3분)로 넣는다. 제출하면 **샌드박스 채점과 AI 코드 리뷰를 둘 다** 한다. |
| Google 로그인 | 온프레미스라 외부 OAuth를 기본으로 켤 수 없다. 설정(OIDC client)이 있을 때만 버튼을 보인다. |

## 2. 규칙이 바뀌는 부분 (기존 PRD 대비)

| 항목 | 기존 | 화면정의서 |
|---|---|---|
| 본질문 수 | 10개 고정 (인성2·이력서2·기업2·직무4) | 질문 수 3~10개 설정, 기본 5개 (자기소개·지원 동기·직무·경험·협업) |
| 질문 분야 | 고정 슬롯 | 인성, 지원 동기, 직무 기술, 프로젝트 경험, 협업 중 선택 + 담당자 직접 입력 / 질문 은행 |
| 꼬리질문 | 본질문당 1개, 전체 4개 | 전체 최대 2개 기본, 0~4회 설정 |
| 시간 | 답변 60 s / 꼬리 45 s | 생각할 시간 5·10·20·30 s, 답변 30·60·90·120 s, 라이브 코딩 3분, 화이트보드 2분 |
| 평가 항목 | 전문성·논리성·구체성·전달력 + 코딩 | 논리성·전달력·표현 및 태도·전문성 + 사용자 정의 항목(상·중·하 기준), 0~60% 5% 단위 |
| 담당자 결정 | 결정 상태 | 합격·보류·불합격 (몇 번이든 변경) |
| 결과 공유 | 지원 = 기업에 공개 | 결과 공유 체크 시에만 기업에 보임, 아니면 연습 모드 |
| 역할 | 지원자·담당자 | 지원자·채용담당자(승인 대기/승인)·운영자 |

## 3. 단계

| 단계 | 범위 | 화면 |
|---|---|---|
| **1. 공통 틀·탐색** | 상단바, 토스트·작은 창 공통 부품, 로그인 탭, 회원가입 창, 비로그인 공고 목록·상세, 이용 안내 | C00, C01, A01, A02, A03, A12, A14 |
| 2. 지원·면접 | 환경 점검, 동의·결과 공유, 이력서 v2, 면접 진행 개편(설정형 질문 수, 생각할 시간, 끼어들기, 라이브 코딩, 화이트보드, 시선), 면접 완료 | A04, A05, A06, A07, A10, A13 |
| 3. 결과·마이페이지 | 리포트 개편, 지원 현황, 프로필, 면접 일정 | A08, A09, A11, A15 |
| 4. 기업 관리 핵심 | 대시보드, 응시자 목록·상세·리포트, 면접 질문 관리, 공고 관리·작성·템플릿·미리보기 | R13, R08, R09, R10, R07, R03, R04, R05, R06 |
| 5. 소통·운영 | 기업회원 가입·인증, 메일 보내기, 일정 관리, 쪽지, 알림, 운영자 | R01, R14, R11, R15, R12, O01, O02 |

단계마다: 마이그레이션 → API와 백엔드 테스트 → 화면 → 타입 검사·빌드 → 실행 중인 스택에서 확인. E2E는 사용자가 요청할 때까지 돌리지 않는다.
