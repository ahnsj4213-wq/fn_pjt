- 대상: `agent-A-architecture.md`, `agent-B-backend-data.md`, `agent-D-frontend-ux.md`, `agent-E-security-qa.md`. 함께 본 자료: `prototypes/README.md`, `prototypes/results-*.txt`, 프로토타입 스크립트(`llm_bench.py`, `ollama_sched_check.py`, `quote_norm_check.py`, `rtc_browser/server.py`).

## 3. 다른 설계안에서 받아들이는 점

- **A**: ai-gw 단일 진입점, `NUM_PARALLEL=1` + 스트림 취소 선점 + `PREEMPTED`(시도 미소모) + `DEADLINE_EXCEEDED` 응답 계약, `num_ctx` 전역 고정, PRD 고정값을 코드 상수로 두는 원칙, `speech` 별도 패키지, 카나리아 로그 검사, 면접 진행기를 rtc 안에 두는 구조.
- **B**: `answer_evaluations`의 "검증된 인용 또는 근거 부족" CHECK, 항목당 인용 1개, 꼬리질문 횟수의 DB 보장(`followups_used` 조건부 UPDATE, 본질문당 유니크), INFRA 오류 시도 미소모와 LLM 탐침 게이트(OQ-23), 10분을 시도 시작부터 재는 해석, `answer_pre_evaluations` 지문 캐시, 질문은행 `real[]` + 앱 코사인.
- **D**: 마이크 트랙 `enabled=false` 이중 방어, 서버 시계 오프셋 계산 방식, 개방 요청이 없어도 서버가 자동 개방, 점검 발화의 문구 일치 불요구, 인용 강조를 서버 오프셋으로만 그리기, 지원자 응답 금지 키 재귀 검사.
- **E**: 인용 대상 범위 한정(해당 답변 단위, 질문 문장 인용 불인정), 최소 8자, 반사실 일관성 시험(SC-78), 인젝션 회귀 세트(SC-77), 꼬리질문·피드백·코드 리뷰 컨텍스트 최소화(SC-74·75·79), 가짜 LLM 프롬프트 캡처. **E-Q15를 받아들여 1단계의 `injection_suspected` 화면 표시를 철회**하고 내부 플래그 기록과 회귀 시험만 남긴다.

## 4. 남은 쟁점 (합의 필요)

1. **인용 정규화 규칙**(E vs C): 실측 근거로 C 규칙(공백 전부·문장부호 제거, 숫자 사이 `.` 보존, 정확 일치만)을 ADR-0008로 고정할지. E의 우려(과잉 정규화로 위조 통과)는 정확 부분 문자열 일치 + 8자 하한 + 답변 단위 한정으로 막는다는 것이 C 입장.
2. **꼬리질문 실제 지연**: 새 답변마다 다른 프롬프트, BATCH 평가와 섞인 조건에서 p95를 다시 재야 한다(F 요청). p95가 약 2초를 넘으면 선택지는 (a) 프롬프트 축소, (b) `NUM_PARALLEL=2`로 RT 접두부 캐시를 유지(사용자 PC Ollama 서비스 설정 변경이라 **사용자 승인 필요**), (c) 표준 어텐션 모델 Qwen3-4B-Instruct-2507과 prefill·캐시 재사용 비교(다운로드 필요, 승인 필요).
3. **꼬리질문 판단 마감값**: PRD 6.2는 5초다. A는 RT 하드 타임아웃 3.2초, C는 기본 5.0초에 실측 후 4.0초를 권장한다. 8.2 "다음 질문 5초"와 함께 지키는 값을 실측 후 하나로 정한다(더 짧게 끊는 것은 "5초 안에 못 정하면 건너뜀"과 충돌하지 않는다는 해석 확인).
4. **STT 모델과 VRAM**: GPU turbo(품질) vs GPU small(VRAM·지연). LLM이 **생성 중일 때** STT 지연과 VRAM 최대치(`nvidia-smi` 200ms 표본)를 측정한 뒤 결정. `num_ctx` 4096/8192도 이때 함께 정한다.
5. **TTS 모델 라이선스**: Supertonic-3 모델 OpenRAIL-M의 용도 제한 승계 의무와 제작사 해산 주장(미확인 미러 출처)을 팀·법률이 확인하기 전까지 MeloTTS(MIT) 측정을 예비로 진행할지. `supertonic` 패키지가 실행 중 모델을 내려받지 않는지(오프라인, AC-22)도 확인 필요.
6. **TTS 하향 경로**(A·C: WebRTC 트랙, D: HTTP 파일): S-1 실측을 근거로 트랙을 기본으로 하자는 제안. F가 OQ로 올릴지 판단.
7. **타이밍 값 통일**: 마감 유예(A 1.5초 / C 0.5초), 끊김 판정·재연결(B 하트비트 15초·재연결 실패 30초·sweeper 90초, D 재시도 1·2·4초 × 3, C 하트비트 10초).
8. **데이터채널 메시지 이름과 명령 경로**: A(`mic_open`, `caption`, `answer_final`), C(`answer.open`, `caption.partial`, `caption.final`), D(`answer_opened`, `caption_segment`, `answer_finalized`)를 하나로 묶고, [답변 완료]를 HTTP(rtc 직접)로 할지 데이터채널로 할지 정한다.
9. **eval_text 저장과 인용 오프셋 기준**(B·D·C): 위 Major 항목의 해결안 채택 여부.
10. **골든셋 Kappa 변형**(가중치 없음 vs 2차 가중)과 근거 부족·답변 없음 개수 표기 방식: 팀 결정.
