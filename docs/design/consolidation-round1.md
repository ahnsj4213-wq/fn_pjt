# 설계 통합 결정 기록 — 1라운드 (통합 담당 F)

- 입력: 독립 설계안 5개(`proposals/agent-A~E`), 상호 리뷰 5개(`reviews/round1-agent-A~E.md`), 조정자 실측(`prototypes/README.md`, `prototypes/results-*.txt`).
- 절차: 협업 규칙 5·6에 따라 Critical(보안·데이터 손실·PRD 위반·실행 불가)은 다수결 없이 근거로 판정했다. 1라운드에서 모든 Critical에 근거 있는 해결안이 나와 2라운드는 열지 않았다. 남은 쟁점은 아래 "임시 결정"으로 닫고 ADR에 기록했다.
- 이 문서의 결정이 각 설계안과 다르면 이 문서가 우선한다. TRD(`docs/trd/`)는 이 결정을 반영한다.

## 3. 받아들인 제안 (요약)

- B의 3상태 분리·허용 전이 표·복합 FK 회사 격리·조건부 갱신·DB 작업 큐(임대·펜싱·인프라 게이트)·Decimal 점수 계산.
- C의 AI 작업 계약 T1~T8, 루브릭 기준 문장 `rubric-v1`, 평가 입력 비식별화, 합불 추천 차단, 프롬프트 인젝션 구분자, manifest 버전 기록.
- D의 면접 화면 전이표(28행 리듀서), 지원자·담당자 모듈 경계(타입·번들 분리), CodeMirror 6, 서버 시계 오프셋, 자동재생 클릭 게이트.
- E의 서버 세션·Argon2id·동기화 CSRF 토큰 + Origin, 라우트 정책 선언과 IDOR 매트릭스, 샌드박스 옵션·SBX 점검 14종·기능 플래그, 품질 게이트 QG-01~14, 카나리아 로그 검사.
- A의 실시간 5초 예산표, AC-22 오프라인 시험 프로필, 로그 허용목록·카나리아, 반입 묶음(이미지·모델 해시).

## 5. 2라운드를 열지 않은 이유

모든 Critical에 제기자가 받아들일 수 있는 구체 해결안이 있고, C5·C6처럼 대립한 항목은 추가 실측으로 판정했다. 남은 쟁점은 취향 차이이거나 팀·법률 결정 사항이라 에이전트 간 추가 토론으로 해결되지 않는다.
