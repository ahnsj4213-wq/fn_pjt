# 개인정보·면접 데이터 보관 기간 명세

- 상태: **법률 검토 전 잠정안** (X-13, OQ-04, OQ-11, OQ-39). 숫자는 설정값이라 법무 결론에 맞춰 바꿀 수 있다.
- 작성 기준: 2026-10-27 현재 스키마(`backend/migrations/versions/*_0001_initial.py`)에 실제로 저장되는 항목.
- 이 문서의 법령 해석은 개발팀의 이해이며 법률 자문이 아니다.

## 1. 데이터를 두 묶음으로 나눈다

| 묶음 | 정의 | 누가 관리하나 | 언제 지우나 |
|---|---|---|---|
| **A. 지원자 개인 보관 데이터** | 지원자가 자기 계정에 두고 관리하는 데이터. 특정 공고와 무관 | 지원자 본인 | 본인이 지우거나 탈퇴할 때 |
| **B. 기업 관리 데이터 (채용 서류)** | 특정 공고에 지원하는 순간 만들어진 데이터. 회사가 채용 판단에 쓰고 회사가 보관 책임을 진다 | 해당 공고의 회사 | 채용 결정 후 정해진 기간이 지나면 **지원 건 단위로 한꺼번에** |

경계: 지원할 때 등록 이력서를 그대로 쓰더라도 지원 건에는 **사본(스냅샷)**이 만들어진다(RES-07). 그래서 지원자가 등록 이력서를 지워도 기업 관리 데이터는 남고, 기업 데이터의 보관 기간이 끝나도 지원자의 등록 이력서는 남는다.

## 2. A. 지원자 개인 보관 데이터

| 데이터 (테이블) | 항목 | 보관 기간 | 현재 구현 |
|---|---|---|---|
| 계정 `users`(지원자) | 이름, 이메일, 비밀번호 해시, 연락처 | **탈퇴할 때까지** (2023년 개정으로 장기 미이용 일괄 파기 의무는 없어짐. 1년 미접속 안내 후 파기는 회사 선택) | 저장 구현, 탈퇴 기능(USR-07, P1) 미구현 |
| 등록 이력서 `resumes` | 성명, 학력, 경력, 프로젝트, 기술, 자격증 | **본인이 지우거나 탈퇴할 때까지** | 저장 구현, 삭제 미구현 |
| 업로드한 이력서 PDF `resume_files`(UPLOAD·REGISTERED) | PDF 원본, 추출 텍스트·항목 | 등록 이력서에 쓰이면 그와 같이. 어디에도 쓰이지 않으면 **7일** | 미구현 |
| 세션 `sessions` | 세션 토큰 해시, CSRF 토큰 | 마지막 요청 후 **2시간** 또는 로그아웃 즉시 (USR-06) | 구현 |
| 로그인 제한 기록 `auth_throttle` | 이메일 HMAC, IP | **24시간** | 정리 작업 미구현 |

탈퇴하면 A 묶음은 즉시 모두 지운다(계정은 익명화). B 묶음은 4절 규칙을 따른다.

## 3. B. 기업 관리 데이터 (채용 서류)

모두 지원 건(`applications`) 하나에 묶여 있고, 기산점은 하나다.

**기산점 D_decision** = 담당자가 처음 합격·불합격을 저장한 시각(`first_decided_at`). 결정이 없으면 공고 마감 시각. 결정이 바뀌어도 기산점은 그대로다.

### 3.1 지원 시점

| 데이터 | 항목 |
|---|---|
| 이력서 스냅샷 `applications.resume_snapshot(_text)` | 지원 시점 이력서 전체 |
| 이력서 PDF 사본 `resume_files`(APPLICATION) | PDF 원본 |
| 개인정보 동의 기록 `consent_records` | 문구 버전, 항목별 동의 여부, 일시 |

### 3.2 면접

| 데이터 | 항목 |
|---|---|
| 답변 음성 원본 (파일) | 지원자 목소리 |
| 답변 텍스트 `interview_answers` | 확정 자막, 비식별화한 평가 입력 |
| 출제 질문 `interview_questions` | 질문, 근거(이력서 인용 포함 가능) |
| 진행 기록 `interview_turns`, `followup_decisions`, `proctor_events` | 시각, 종료 사유, 꼬리질문 판단, 화면 이탈 |
| 저장하지 않는 것 | 카메라 영상(INT-08), 점검 단계 발화 |

### 3.3 코딩테스트

| 데이터 | 항목 |
|---|---|
| 임시 저장 코드 `coding_attempts` | 작성 중 코드 (최종 제출 직후 비움) |
| [실행] 출력 `coding_runs` | 출력·오류 앞부분 (7일) |
| 최종 제출·채점 `coding_submissions`, `coding_test_results` | 코드, 통과 여부 |

### 3.4 평가·결정

| 데이터 | 항목 |
|---|---|
| 문항 평가 `answer_evaluations`, `answer_pre_evaluations` | 점수, 답변 인용, 코멘트 |
| 리포트 `recruiter_reports`, 지원자 피드백 `candidate_feedback` | 점수, 총평, 강점·개선점 |
| 담당자 메모 `recruiter_notes` | 담당자가 쓴 지원자 메모 |
| 평가 버전 기록 `evaluation_runs` | 모델·프롬프트·루브릭·가중치 버전 (개인정보 없음) |
| 결정 이력 `decision_history`, 지원 건 상태 | 결정 값, 결정자, 일시 (개인정보 없음) |

## 4. 보관 기간을 일괄로 정하는 방법

항목마다 기간을 따로 두지 않고, **기업 관리 데이터는 지원 건 단위로 3단계**, 지원자 데이터는 계정 단위 한 규칙으로 묶는다. 설정값은 3개다.

| 단계 | 대상 | 기간 (설정값) | 근거 |
|---|---|---|---|
| **1단계: 음성** | 답변 음성 원본 | D_decision + **30일** (`RETENTION_AUDIO_DAYS`) | PRD 8.5. 원문 중 가장 민감하고 텍스트로 대체 가능 |
| **2단계: 채용 서류 일괄** | 3.1~3.4의 나머지 전부: 이력서 스냅샷·PDF 사본, 답변 텍스트, 질문, 진행 기록, 제출 코드, 평가, 리포트, 피드백, 메모 | D_decision + **180일** (`RETENTION_CONTENT_DAYS`) — 지원 건 하나를 통째로 지운다 | 채용절차법 제11조 상한(채용 확정 후 14~180일) |
| **3단계: 기록** | 동의 기록, 결정 이력, 평가 버전 기록, 지원 건 상태 행(개인정보 없이 ID만), 담당자 접속기록(감사 로그) | **3년** (`RETENTION_RECORD_DAYS`) | 접속기록 최소 1년(안전성 확보조치 기준), 남녀고용평등법 채용 서류 3년 보존, 분쟁 대비 |

지원자 개인 보관 데이터(A)는 기간 없이 **"본인 삭제 또는 탈퇴 시"** 한 규칙이다. 세션·로그인 제한 기록처럼 운영상 짧게 쓰는 데이터는 데이터 목적상 자동 만료되므로 위 설정과 무관하다.

일괄 방식의 장단점:

| 장점 | 단점 |
|---|---|
| 지원 건 하나를 한 번에 지우므로 일부만 남는 일이 없다 | 메모·[실행] 출력처럼 더 짧아도 되는 데이터도 180일 둔다 (최소화 원칙상 약간 손해) |
| 동의 문구에 기간을 세 줄로 고지할 수 있다 | 남녀고용평등법 3년 보존 대상을 법무가 "리포트 점수·결과까지"로 보면 2단계에서 그 부분만 3단계로 옮겨야 한다 |
| 법무 결론이 바뀌어도 설정값 3개만 바꾸면 된다 | |

동의 문구 예시(법무 검토 후 확정):
> 보유 기간: 답변 음성은 채용 결정 후 30일, 이력서·답변·코딩 결과·평가 리포트는 채용 결정 후 180일 뒤 파기합니다. 동의·결정 기록과 담당자 열람 기록은 개인정보를 제외하고 3년간 보관합니다. 등록 이력서와 계정 정보는 탈퇴하면 즉시 파기합니다.

## 5. 회원 탈퇴 시

1. A 묶음은 즉시 파기(계정 익명화, 등록 이력서·업로드 PDF 삭제).
2. B 묶음의 1·2단계(음성, 채용 서류)도 즉시 파기한다. 단 법무가 법정 보존 대상이라고 판단한 서류는 분리 보관 후 기간 만료 시 파기.
3. 3단계 기록은 개인정보 없이 남는다.
4. 응시 진행 중이면 응시가 끝난 뒤 처리한다(OQ-B7).

## 6. 백업·로그

| 대상 | 기간 |
|---|---|
| DB 백업 | 30일 순환. 원본에서 지운 데이터는 늦어도 30일 뒤 백업에서도 사라진다(동의 문구에 고지) |

## 7. PRD·현재 구현과 다른 점 (법무 확인 필요, OQ-39)

| 항목 | PRD 8.5 / 현재 구현 | 이 문서 |
|---|---|---|
| 채용 서류(텍스트·리포트·코드·이력서) | 365일 (`retention_content_days=365`, 동의 문구 365일) | **180일** (채용절차법 상한) |
| 동의·결정·접속 기록 | 기간 없음 | 3년 (`RETENTION_RECORD_DAYS` 신설 필요) |
| 자동 삭제 집행 | 미구현 (SEC-07, P1) | 지원 건 단위 일괄 삭제 작업으로 구현 예정 |

법무 확인 전에는 구현값과 동의 문구를 바꾸지 않는다.
